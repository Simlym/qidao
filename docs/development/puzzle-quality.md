# 题目反馈、人工审核与版本修订

题库导入及来源说明见[题库导入与管理](puzzles.md)。本文说明题目进入训练后如何收集问题、核对多解、修订答案并保留历史。

## 用户反馈

登录用户在公共标准象棋的“训练”页点击“题目有问题？反馈”，选择答案／应手错误、其他可行解、局面、难度分类或其他问题，填写说明；可附坐标着法或文字建议。

反馈不结算成绩、不修改题解，也不会因有人反馈就自动下架题目。未发布、已下架和私人题目不能通过公共反馈入口提交；游客需先登录。

用户可在“设置 → 我的题目反馈”分页查看自己的提交与管理员回复，也可从训练页展开最近记录。不同账号的反馈隔离；删除账号后，管理员队列匿名保留问题记录，新注册的同名账号不会继承旧反馈。

同一用户对同一道题、同类问题已有待处理反馈时，返回原记录，避免重复排队。客户端网络重试沿用请求标识；相同标识不能用于不同内容。已处理后可再次反馈新的问题。

## 管理员处理队列

打开“后台 → 题库 → 问题反馈”，按待处理、已处理、未采纳或全部筛选。队列显示题号、问题类型、用户说明与建议着法。

1. 点击“审核此题”，查看原题及版本历史。
2. 比较各题解分支，使用“上一步着法／下一步着法”核对棋盘变化。
3. 需要更改答案时创建修订版，完成审核与发布。
4. 返回反馈队列，填写给用户的回复，标为已处理；不采纳也必须说明理由。

关闭反馈不等于自动批准题目；发布修订版也不自动关闭相关反馈。处理说明会展示给反馈用户，内部审核依据单独保存在审核记录中。已处理的结果不能被另一位管理员静默覆盖。

## 人工审核与多解

编辑窗口的“多解核对与人工审核”显示已录入的分支、逐步棋盘、审核依据和最近 50 条审核记录。

- “记录审核通过”：要求填写依据，并重新执行基础局面／走法检查。
- “要求修改并下架”：记录原因；若该版本已经发布，则立即下架。
- 每条记录保存审核人、时间、结论、依据和题目内容指纹。
- 审核时题目若已被另一位管理员修改，拒绝提交旧结论，需刷新后重新核对。
- 修改题解、局面、分类、难度或标签会使当前人工审核失效；旧审核记录仍保留并标为旧内容。有过人工审核的题，内容变更后需重新通过审核才能再次发布。

人工审核与原有规则／引擎校验标记分别展示，不把人工判断写成引擎证明。逐步播放只能展示录入分支，不能自动穷举所有应手。尤其是多步杀，主线合法、终点将死仍不能证明强制杀或唯一解；人工说明应明确核对范围，需要时先用离线引擎或求解工具验证。

## 创建与发布修订版

已经发布或有学习记录的题目不能直接改写局面和题解。应使用“创建修订版”：

1. 在最新版本窗口展开修订表单，修改题解、局面或教学信息，填写修订原因。多个可接受分支用 `|` 分隔。
2. 保存为新的待审核题号，版本递增为 v2、v3……。原版继续保持原状态。
3. 在新版窗口核对分支并记录人工审核通过。
4. 点击“发布此版本”，或选中新版批量发布。事务内下架该版本族的旧版，再发布新版；失败时整体回滚。

修订版必须先人工审核通过。普通新导入题仍兼容原有“检查后发布”流程；一旦留下人工审核记录，后续内容变更也必须重新审核。任何题目发布时都会再做基础合法性检查。

同一版本只能创建一个直接后续版本，重复请求相同内容返回已有版本；不同修订不会相互覆盖，应先查看已经创建的版本。可以继续基于最新的待审核版本创建下一版，但只有最新版本可以发布。

旧版不能重新发布。批次整体发布会跳过已有后续版本的旧题，避免恢复旧答案。想恢复某个旧答案，应基于最新版创建一个新的修订，再审核发布，保留完整修订链。

新版的局面若与其他独立题目冲突，发布会被拒绝，交由管理员核对；同一版本族可以使用相同局面、更正或补全题解。

## 学习记录如何保留

旧题号、答案、作答记录、复习状态、解题会话和棋局引用均保留。新版使用新题号，不继承旧答案下的已学状态、评分或复习进度，以免把错误题解的成绩套到修正版。

下架的旧版不再出现在新题、复习、目录、闯关或新测评中。若用户正训练旧版，下一次校验或提交会提示题目／会话已不可用，可以返回每日训练重新取题；不会把该请求当成答错结算。已保存的历史记录仍在。

分类、难度和标签仍允许管理员编辑；若影响已有人工审核，会清除当前通过状态。题解或局面修改则必须遵守版本约束。

来源、许可证与原导入批次随修订保留；修订原因与操作人另行记录。题库 JSON 导出主要用于内容与来源分发，不会迁移用户反馈、内部审核或学习历史，也不会在另一实例重建原版本关系。

## 部署与迁移

迁移 `202610290006` 为题目增加版本及人工审核状态，并创建 `puzzle_reports` 与 `puzzle_quality_reviews`。旧题默认为 v1、待人工审核，其发布状态和原校验标记保持不变，不强制全库重新审核。

升级步骤遵循[后端部署与备份文档](../deployment/backend.md)，应用启动会自动执行迁移。版本变更以版本根节点的数据库写锁串行处理，兼容 SQLite 与 PostgreSQL；创建、审核、发布的并发行为有真实 PostgreSQL 回归覆盖。

仍待后续实现：自动引擎多解证明、后台求解长任务、上游定时同步、反馈通知推送与人工审核分工。当前处理结果通过页面查看，不发送邮件或其他外部消息。
