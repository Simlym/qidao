# 产品日志的范围与维护

后台「日志中心」围绕产品操作的结果组织信息。运行事件按业务范围筛选，同一次操作的阶段和技术输出合并到详情；管理审计保存登录失败和敏感管理操作。概览数字只统计当前加载窗口，不代表全站业务指标。

## 常用范围

| 范围 | 记录的关键事件 | 不记录的正常流量 |
| --- | --- | --- |
| 账号与安全 | 注册成功、登录成功/失败、后台访问拦截 | 当前用户查询、普通游客访问 |
| 对弈与棋谱 | 开始对弈、存盘、导入、删除、服务请求失败 | 每步落子、局面状态查询 |
| 复盘分析 | 提交任务、完成、失败、空棋谱取消 | 分析进度轮询、每步分值 |
| AI 服务 | 模型调用结果与耗时、生成结果、额度不足/退回/结算待确认 | 提示词、思考内容、模型正文 |
| 题库管理 | 导入预览/确认、状态变更、编辑、修订、审核与反馈处理 | 题目浏览和列表翻页 |
| 训练学习 | 提交一道题的训练结果、教练计划更新 | 检查每步答案、取下一题 |
| 引擎服务 | 下载/导入/检测开始、阶段、结果、取消、进程诊断 | 高频连续评分的正常响应 |
| 系统运行 | 服务启动、未处理异常、限流告警 | 健康检查、日志自动刷新 |
| 后台管理 | 积分调整及未单独归类的敏感管理操作 | 管理列表正常读取 |

## 新功能如何维护

1. 在 `backend/app/core/product_log.py` 的 `EVENTS` 中登记稳定事件标识、中文名称和业务范围。分类接口直接读取 `CATEGORIES`，前端无需另维护分类清单。
2. 普通关键 HTTP 操作可登记到 `REQUEST_EVENTS`，纯 ASGI 中间件只记录结果、耗时和路由模板，不读取请求/响应正文。高频操作只保留异常；不要给每次轮询加成功事件。
3. 后台任务、模型降级等不能从 HTTP 状态判断结果的操作，在实际完成、失败或取消的位置调用 `emit_event()`。长任务必须有终态，不能只留下“进行中”。不能确认额度已退回时记录“结算待确认”，不要宣称退款成功。
4. 管理审计通过 `security_log.admin_action()` 记录，在 `ADMIN_ACTIONS` 中登记中文动作和归属；数据库仍保留原始动作标识便于追溯。
5. 一个操作的阶段共用 `operation_id`。普通请求自动带 `request_id`；引擎安装和 AI 生成传播操作上下文，过程、异常与最终结果可一起查看。诊断原文保留在技术详情中，不拼到主列表标题。

```python
from app.core.product_log import emit_event

emit_event("analysis.completed", actor=username, resource=f"棋谱 #{game_id}",
           operation_id=run_key, duration_ms=elapsed_ms, details={"moves": move_count})
```

结果约定：`success` 成功、`failed` 失败、`warning` 降级或需要注意、`rejected` 请求未执行、`running` 进行中、`cancelled` 已取消。错误记录可传 `exc_info=True`，堆栈仅在管理员技术详情和后端日志中展示。

## 数据与保留

- 运行事件保存在当前进程最多 500 条原始记录的有界内存缓冲中，服务重启后清空。页面每 5 秒更新，可暂停；一次操作的多条过程记录只算一个摘要。多进程部署的运行窗口分别属于各工作进程。
- 管理审计使用既有 `security_logs` 表，重启不丢失，分页查看。此改动不把所有业务事件写入数据库，也不把局部窗口的数量当成全站统计。
- 禁止记录密码、认证头、token、密钥、提示词、模型正文、原始请求/响应体或揭棋真实隐藏身份。只传必要的账号、对象编号、动作、结果和耗时；内存输出再做凭据与密码摘要脱敏。
- 修改事件采集时验证分类、终态、操作合并、脱敏及“正常高频请求不产生噪声”。修改页面时验证筛选、详情、审计翻页、自动刷新取消和移动端布局。
